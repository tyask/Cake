モデルは **`gpt-6.1-terra`** をおすすめします。画像入力と構造化出力に対応し、写真から必要な項目を取り出す用途に適しています。標準料金は100万トークンあたり入力$1・出力$5です。レシートでの読み取り精度は実装時に確認します。[OpenAI公式仕様](https://developers.openai.com/api/docs/models/gpt-6.1-terra)

**開発計画**

目的は、レシートなどの写真から明細の入力作業を減らすことです。

- 「明細を追加」にカメラアイコン付きの「写真から入力」ボタンを追加します。スマートフォンでは背面カメラでの撮影を優先し、PCや非対応ブラウザでは画像選択を利用します。
- 1枚の写真から1取引を読み取ります。取引日時、取引先、税込合計金額、購入内容をまとめたメモを補完します。
- カテゴリは、読み取った取引先を使い、既存の履歴ベースの補完処理で設定します。候補がなければ未分類、手動選択済みならその値を保持します。
- 読み取れた項目をフォームへ反映し、自由に修正できるようにします。取引方法・支払者・種別は現在の値を保持し、配分は既存の取引先ルールと手動調整の扱いを維持します。
- 読み取れない値は推測で埋めません。日付だけ読めた場合は日付のみ反映し、時刻の確認を促します。
- 自動登録はせず、既存の「追加する」で保存します。複数レシートの一括取込、画像の保管、DB構造の変更は今回の対象外です。

**受入条件**

- [ ] AC-01：カメラボタンから撮影・画像選択でき、撮影キャンセル時は入力を保持する。
- [ ] AC-02：日時・取引先・金額・メモを補完し、未読取項目を明示して修正できる。
- [ ] AC-03：カテゴリは既存方式で補完し、候補なし・手動設定済みを適切に扱う。
- [ ] AC-04：解析中の二重実行を防ぎ、失敗時は入力を保持して再試行できる。画面を閉じた後や家計切替後の応答は反映しない。
- [ ] AC-05：認証と家計への所属を確認してからOpenAIを呼び、APIキーをブラウザへ公開しない。
- [ ] AC-06：解析だけでは明細を保存せず、確認後に既存の登録処理で保存できる。

実装はサーバー側からOpenAI Responses APIを呼び、構造化した結果を既存の入力制約で検証します。画像は縮小して送信し、形式・容量を検証します。Cake側では画像を永続保存しません。`OPENAI_API_KEY`とモデル設定をサーバー環境変数に追加します。

標準の機能追加工程として、UI・画像解析API・カテゴリ補完の接続・関連文書更新を行います。認証、画像不正、未読取、API失敗、遅延応答、保存内容をテストし、lint・型チェック・自動テスト・build、別Agentレビュー、CI・Preview検証まで進めます。実機のカメラ起動は手動確認項目にします。実APIの検証には利用可能なキーが必要で、本番への設定・公開は別途扱います。
