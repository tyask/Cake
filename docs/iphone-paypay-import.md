# iPhoneからPayPay CSVを取り込む・実機検証手順

PayPayで共有したCSVをiPhoneのショートカットでテキストにし、Cakeへ貼り付けます。利用者が「ファイルに保存」して選び直す操作を省くための手順です。PayPay側のCSV作成・ダウンロードや、iOSが扱う一時ファイルは必要です。

CSV本文はCakeのブラウザ内で解析します。内容確認時は重複照会に必要な取引ID等を送り、登録操作時に選択した明細を送ります。貼り付けだけで明細は登録されません。

PayPayの共有からファイル本文を受け取れるか、ショートカットから意図したブラウザを開けるかは実機で確認します。iPhoneのSafari・ホーム画面WebアプリはWeb Share Targetに対応していないため、Cakeを直接共有先として追加する方式は使いません。

## 1. 対象のPreviewを開く

1. 対象PRの最新チェックとPreview情報を確認し、現在の変更に対応する準備完了済みのPreview固有URLを取得します。対象の照合方法は[開発・QA運用手順](development-workflow.md#4-previewの特定と認証)を参照してください。
2. iPhoneのSafariでそのURLを開き、必要なら本人のVercelアカウントで認証します。Vercelの保護認証とCakeへのログインは別です。保護設定を解除したり、認証トークンをショートカットへ入れたりしません。
3. Cakeのログイン画面で「テストユーザーA」を選び、「テスト共有家計」が選択されていることを確認します。テストユーザーのボタンや共有家計が見つからない場合は、別環境で代用せずPreviewの準備状態を確認します。
4. 「取込」を開きます。直リンクは `https://<Preview-host>/?tab=import` です。`<Preview-host>` は上で確認したPreviewのホスト名に置き換えます。

この検証では本番へ登録しません。PRの一時URL・認証情報・実行結果はこの文書へ追記せず、必要な結果だけをPRの検証報告へ残します。Previewが更新されたら、ショートカットに設定するURLも現在の対象へ合わせます。

## 2. サンプルCSVで貼り付けを確認する

最初はPayPayの実データを使わず、次のCSVをヘッダーから末尾までコピーします。コード枠の記号は含めません。支払い2行と、対象外になる受け取り1行です。

```csv
取引日,出金金額（円）,入金金額（円）,取引内容,取引先,取引方法,取引番号
2026/07/15 20:01:44,"1,200",-,支払い,iPhone検証スーパー,PayPay残高,iphone-paste-payment-1
2026/07/14 09:00:00,500,-,支払い,iPhone検証カフェ,PayPayポイント,iphone-paste-payment-2
2026/07/13 10:00:00,-,300,受け取り,iPhone検証受け取り,PayPay残高,iphone-paste-receipt-1
```

1. Cakeの貼り付け欄「CSVの内容」を長押しし、Safari標準の「ペースト」で貼り付けます。自動的なクリップボード読取は行いません。
2. 先頭が `取引日,出金金額（円）` から始まり、各取引が改行されていることを確認して「内容を確認」を押します。
3. 確認表で次を確認します。初めてこのサンプルを使う家計では、支払い2件が取込対象になります。すでに同じサンプルを登録済みなら、重複として選択できないことが正しい動作です。

| 確認する項目 | 期待する内容 |
| --- | --- |
| 取込先・支払者 | 「テスト共有家計」・「テストユーザーA」。取込先と支払者を確認してから登録する |
| 件数 | 支払い2件だけが表示され、受け取りは表示されない |
| 日本語・金額 | 「iPhone検証スーパー」が1,200円、「iPhone検証カフェ」が500円。引用符で囲まれたカンマ付き金額も正しく読める |
| 日時 | スーパーが2026年7月15日20:01:44、カフェが7月14日09:00:00の日本時間。必要なら明細の詳細を開いて秒まで確認する |
| 費用区分・割合 | 家計のルールと参加者に応じた値になり、登録前に確認・変更できる |
| 重複・エラー | 初回はエラーなし。登録済みと同じ取引日・取引番号は重複として選択されない |

4. **最初の確認では「キャンセル」を押します。** 取引明細へ移動して、サンプル明細が新規登録されていないことを確認します。ここで確認するのは明細が増えないことであり、ログインを含む全操作がDB無変更だったという意味ではありません。

## 3. 共有用ショートカットを手作業で作る

自動配布用のショートカットは用意せず、iPhoneの「ショートカット」アプリで次の内容を作成します。iOSの版によってアクション名や設定場所が異なる場合があります。

1. 新規ショートカットを作り、名前を「Cakeに取り込む」にします。
2. 詳細設定で「共有シートに表示」をオンにし、共有シートから受け取る入力を「ファイル」にします。
3. 「入力からテキストを取得」を追加し、対象を「ショートカットの入力」にします。ファイル名やファイルのURLだけをコピーする設定にしないでください。
4. 「クリップボードにコピー」を追加し、前のアクションで取得したテキストを渡します。「ローカルのみ」をオンにし、「有効期限」は実行時から5分後など、貼り付けに必要な短時間に設定します。日時の入力が必要な場合は「現在の日付」を5分進めた値を使います。
5. 「URL」アクションに `https://<Preview-host>/?tab=import` を設定し、「URLを開く」へ渡します。URLへCSV本文、クリップボードの内容、認証情報は付けません。

URLを開くと普段使うホーム画面Webアプリへ戻るとは限りません。まずSafariで検証し、開いたブラウザでVercel認証・Cakeログイン・取込先を改めて確認します。別ブラウザやログイン画面が開く場合は、その状態を検証結果に記録します。

## 4. PayPayから共有して確認する

1. PayPayの「取引履歴」から対象期間のダウンロードを申請し、CSVを開ける状態にします。最初は短い期間で確認します。
2. CSVを表示した画面の共有から「Cakeに取り込む」を選びます。ショートカットが出ない場合は、共有シート表示と受け取る入力の種類を確認します。
3. Cakeで「CSVの内容」を長押しして「ペースト」します。コピーの有効期限を過ぎた場合はPayPayから共有し直します。
4. 貼り付けた内容が `取引日` から始まるCSV本文か確認します。**`https://...` などのURLやファイル名しか渡らない場合はそこで止め、本文が受け取れなかったことを報告します。** URLを自動取得する処理を足したり、認証情報をコピーしたりしません。
5. 「内容を確認」を押し、取込先、支払者、件数、日本語、金額、日本時間の日時、重複表示を元のCSVと見比べます。画面が狭い場合は明細の詳細を開きます。
6. 実データではまず「キャンセル」で終え、登録されていないことを確認します。検証後は入力欄やプレビューを閉じ、クリップボードの有効期限まで他の場所へ貼り付けないでください。

この手順が通れば、手動でファイルを保存して選び直す工程を省けます。「PayPayから共有」後のショートカット実行と、Cake上の貼り付け・確認・登録は利用者の操作として残ります。

## 5. 登録・重複まで確かめる場合

登録操作は、専用DBを使う対象PRのPreviewでのみ行います。サンプルCSVを使い、登録前の明細を確認してから「選択した2件を登録」を押してください。成功後に取引明細を再表示し、2件の内容を確認します。

同じサンプルを再度貼り付けて「内容を確認」を押すと、登録済みの2件が重複となり、再登録の対象から外れることを確認できます。その後はキャンセルします。後片付けを行う場合は今回登録したサンプル明細だけを削除し、再読み込み後にその2件が残っていないことと、既存の明細を変えていないことを確認します。途中で失敗したら、登録・削除を繰り返す前に実際の残存状態を確認します。

## ファイル選択で取り込む場合

ショートカットが使えない場合も、従来の方法を利用できます。PayPayのCSVをiPhoneの「ファイル」へ保存し、Cakeの取込画面で「ファイルを選択」から指定します。取込先と支払者を確認し、同じ確認表で内容を確認してから登録します。検証の最初は、この経路でもキャンセルして終えてください。

## うまくいかない場合の報告

- iPhoneのiOS版、ブラウザ名、PayPayアプリの版。
- 失敗した段階（共有先選択、テキスト化、Cake起動、貼り付け、内容確認、登録）と表示メッセージ。メッセージに個人情報が含まれる場合は伏せます。
- 受け取ったものがCSV本文・URL・ファイル名のどれだったか、サンプルCSVでは再現するか。
- 対象PR、Safariタブかホーム画面Webアプリか、Vercel認証やCakeログインへ戻されたか。

CSV全文、実際の取引先・金額・取引番号、ダウンロードURL、認証情報、Cookieは報告へ貼り付けません。スクリーンショットも実データと秘密値を隠してください。実機で確認した結果はPRの検証報告に残し、未確認の段階は成功と扱いません。
